bonk

Create bootable media (USB drives and external disks)

Usage: bonk [OPTIONS] [COMMAND]

Commands:
  disk          Disks: list and detail
  catalog       Images offered by the signed catalog
  cache         Downloaded images: list and cleanup
  list          List the disks Bonk can write (shortcut for `disk list`)
  info          Detail of a disk (shortcut for `disk info`)
  write         Write an image to a disk, then verify it (`--simulate`: to an image file)
  verify        Compare a disk to an image, writing nothing
  repair-gpt    Repair the GPT of a disk or an image
  format        Return a disk to storage use: table, partition, filesystem
  capabilities  What this host allows, and why not the rest
  diagnose      Support report as JSON: system, rendering, disks and verdicts, secrets masked
  debug         Low-level disk view, read-only: system sources, step-by-step filter, partition tables
  explain       Explain an error code (`bonk explain E1003`) or list all codes
  config        Persistent settings: list, get, set, reset
  schema        JSON Schema of a command's `--json` output
  completions   Shell completions: bash, zsh, fish, powershell, elvish
  serve         Headless service: drive Bonk with JSON on standard input and output, without a window
  gui           Open the window (like `bonk` alone)
  help          Print this message or the help of the given subcommand(s)

Options:
  -v, --verbose...               Detailed log (-v), then very detailed (-vv) on standard error
  -q, --quiet                    Keep only the result: no progress line, and only errors in the log
      --log-file <PATH>          Also write the log to this file (appended)
      --log-format <LOG_FORMAT>  Log format: text, or one JSON event per line [possible values: text, json]
      --fixture <FILE>           Replay a captured enumeration (`bonk diagnose --capture`) instead of reading this system: reads, `--dry-run` and `--simulate` only, never a write to a disk
      --proxy <URL>              Send all network traffic through this proxy (`BONK_PROXY`): socks5h:// only, such as Tor at socks5h://127.0.0.1:9050. If it cannot be reached, Bonk fails instead of connecting directly
      --no-gui                   Never open the window: without a command, print the help and fail, for scripts
      --no-color                 No color in the help and usage errors (`NO_COLOR` has the same effect)
  -h, --help                     Print help
  -V, --version                  Print version

bonk disk write

Write an image to a disk, then verify it

Usage: bonk disk write [OPTIONS] <TARGET> [SOURCE]

Arguments:
  <TARGET>
          Stable identifier of the disk (see `bonk list`); with --simulate, path of the target image file

  [SOURCE]
          Image to write: a file (.img, .iso, .gz, .xz, .zst; the format is recognized by its content) or an https:// address to download, with its hash

Options:
      --simulate
          The target is an image file (created if missing, with --size), not a disk: replays the operation without hardware

  -v, --verbose...
          Detailed log (-v), then very detailed (-vv) on standard error

  -q, --quiet
          Keep only the result: no progress line, and only errors in the log

      --size <BYTES>
          Size of the target image created by --simulate (decimal or 0x...); by default that of the source image when it is raw

      --log-file <PATH>
          Also write the log to this file (appended)

      --show-internal
          Allow internal non-system disks (stronger warning)

      --allow-virtual
          Test mode: allow virtual disks

      --log-format <LOG_FORMAT>
          Log format: text, or one JSON event per line
          
          [possible values: text, json]

      --fixture <FILE>
          Replay a captured enumeration (`bonk diagnose --capture`) instead of reading this system: reads, `--dry-run` and `--simulate` only, never a write to a disk

      --trace-io[=<TRACE_IO>]
          Log each block access (offset, duration, checksum); `=data` adds the first bytes, for an image file only

          Possible values:
          - metadata: Offset, length, duration and checksum of each access
          - data:     With the first 16 bytes: for image files only

      --elevate <ELEVATE>
          Missing rights: auto (ask the system) or never (the caller's rights only)

          Possible values:
          - auto:  Ask for system authorization when opening the disk
          - never: The caller's rights only
          
          [default: auto]

      --proxy <URL>
          Send all network traffic through this proxy (`BONK_PROXY`): socks5h:// only, such as Tor at socks5h://127.0.0.1:9050. If it cannot be reached, Bonk fails instead of connecting directly

      --progress <PROGRESS>
          Progress: auto, json (one event per line) or none

          Possible values:
          - auto: A progress line on standard error if it is a terminal, nothing otherwise
          - json: One JSON event per line on standard output
          - none: No progress
          
          [default: auto]

      --json
          Result as JSON

      --image <ID>
          Image of the signed catalog (`bonk catalog list`): its official link and hash are used

      --catalog-url <URL>
          Catalog address (`BONK_CATALOG_URL`); its signature is checked wherever it comes from

      --yes
          Confirm the write: without --yes or --force, Bonk does nothing (it never asks a question)

      --dry-run
          Describe what would be done without writing to the drive; an address is still downloaded into the cache, since the analysis needs the image

      --sha256 <HEX>
          Published SHA-256 hash of this file: checked before touching the drive

      --sha256-file <PATH_OR_URL>
          Published hash file (SHA256SUMS), path or https:// address: the hash is read under the name of the image

      --cache-dir <DIR>
          Download directory; by default the user's cache directory

      --mode <MODE>
          auto: analyze the image, extract a Windows ISO and refuse what would not boot; raw: write the bytes as they are; extract: require a Windows ISO

          Possible values:
          - auto:    Extract a Windows ISO; refuse a truncated image or one that would not boot as written
          - raw:     Write the bytes as they are, whatever the analysis says
          - extract: Copy the files of a Windows installation ISO to a FAT32 partition; auto chooses it by itself
          
          [default: auto]

      --table <TABLE>
          Partition table of a Windows drive; boot stays UEFI in both cases
          
          [default: gpt]
          [possible values: gpt, mbr]

      --no-verify
          Do not read the drive back after writing

      --no-repair-gpt
          Do not repair the backup GPT after writing

      --force
          Confirm like --yes, and allow an internal disk admitted by --show-internal, without a question. Never a system disk: the safety filter stays in charge

      --no-color
          No color in the help and usage errors (`NO_COLOR` has the same effect)

  -h, --help
          Print help (see a summary with '-h')
